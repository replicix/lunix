# xfstests comparison (`-g quick -x dangerous`, 16 GiB TEST and SCRATCH): Lunix against the loop reference of the same session

"Ran" below means executed: tests xfstests reported as `not run` are neither passes nor failures (the first version of this
comparison counted them as passes). GNU coreutils go first in PATH for ext4 (the Rust coreutils of the host broke 244 ext4 tests;
the message `invalid value for one of the arguments` is absent from all three ext4 runs). Raw data: `raw/m15-xt2-*`
(ext4, rerun), `raw/m15-xfstests-*` (xfs).

## Verdict

- **ext4, 64 KiB and 16 KiB: no test that runs on both fails on Lunix only except ext4/054, which is a device-property difference, not
  a defect.** The reference ran 411 tests (273 not run), 13 failed; Lunix ran 404 (280 not run), 14 failed (the same 13 plus ext4/054).
  - ext4/054 runs `mkfs.ext4 -b 1024`; the Lunix device has a 4096-byte logical block ("Invalid argument while setting blocksize; too
    small for device"), the loop reference 512.
  - The 7 tests that run on the reference and are not run on Lunix are the same cause (ext4/035, generic/114, 240, 366, 450, 538,
    641: 1 KiB file system blocks or 512-byte alignment impossible on a 4096-byte-sector device).
  - The 13 failures on both are reference/host environment failures (quota tools that cannot stat a tmpfs, no `newring`/keyring,
    statfs permission, stripe geometry): reasons below.
- **xfs, 64 KiB and 16 KiB: xfs/129, xfs/234 and xfs/253 are a sector-size effect, not a Lunix defect.** They fail on a loop reference
  with 4096-byte sectors (`losetup --sector-size 4096`, run `m15-xt2-ref-xfs4k`) exactly as on Lunix (both "Failed 3 of 3",
  output mismatch). With the default 512-byte loop reference they were counted as Lunix-only failures.
  - 26 more xfs tests run on the reference and are not run on Lunix, all for the same reason (`block size 1024 cannot be smaller than
    sector size 4096`, 512-byte O_DIRECT alignment, `device block size 4096 greater than 512`).
  - They need a 4096-byte-sector reference to compare; not run.
- No test hung or was killed by the watchdog (`stalled-tests.txt` is absent in all runs); xfs/118 stays excluded (it hung on the
  reference).
- The 16 KiB and 64 KiB runs give identical results.

## xfs/129, xfs/234, xfs/253 on a 4096-byte-sector reference

| run | result |
|---|---|
| loop reference, `--sector-size 4096` (`m15-xt2-ref-xfs4k`) | xfs/129, xfs/234, xfs/253: failed (3 of 3), `xfs_mdrestore` cannot restore the metadump |
| Lunix 64 KiB (`m15-xt2-l64-xfs3`) | xfs/129, xfs/234, xfs/253: failed (3 of 3), same |

Both sides fail the same way: a sector-size interaction of the tool with a 4096-byte-sector device, not a Lunix defect.
