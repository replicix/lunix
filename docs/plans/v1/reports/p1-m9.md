## Semantics fixed here

- API: `destage_cut(&OverlayCut, &DestageDeps) -> Result<DestageOutcome, DestageError>`. The cut is borrowed (the caller needs it for `Overlay::release`).
- Workers run assemble, scan, id, dedup, compress, seal on jobs of `min(16, 1 MiB / chunk)` chunks. The calling thread packs in chunk order and applies one `MapTxn` at the end, so a failure applies nothing to the map.
- **Determinism:** a chunk equal to an earlier one in the same cut is resolved in order (first in LBA order is stored, the rest point at it). A worker that reaches an id already claimed skips compression; the packer takes the sealed extent from the claimer's slot. Layout is independent of thread timing (test over 1, 2, 3, 8 workers).
- **Segments:** full segments are sealed by the cut as they roll. The last stays open in `DestageOutcome::open`; the caller seals it at C4 (`seal_open`), then calls `insert_into_index`. `DestageOutcome::segments` lists every segment with its extents, `write_seq` range and bytes, so the caller can reserve and name them.
- **Dedup:** `get_for_dedup`; `Verified` taken as is; `Hinted` confirmed by reading the extent with `OpenExpect.chunk_id = Some(full id)` (all 32 bytes plus tag/AEAD through the codec). Any data error (NotFound, Corrupt, Auth, Unsupported) or an absurd hint (`clen` 0 or above the chunk size, not read at all) is a miss. Host `Io` propagates.
- **R1:** the base read passes the leaf prefix, the confirmation read the full id, both the chunk size. A stale or wrong hint falls back to `get_by_prefix`, each candidate confirmed against its full id; with no candidate the original `Auth` stands. A lean map (`id_len` 0) has no fallback.
- **Compression:** `auto` = LZ4 probe of the first 4096 bytes, raw if `saved * 100 < 6 * probe_len`, else zstd at the policy level; any codec output not smaller than the input is stored raw. Backpressure: the depth is the number of jobs not yet started when a job starts (depends only on the job index, so it is deterministic); above `lz4_depth` use LZ4, above `raw_depth` store raw. Defaults 4096 and 16384 jobs.
- Space: destage returns `ReadOnly` if the gate is read-only and calls `fatal_io` on a host `EIO`. The ledger reservations (C2 headroom, C4 true-up) stay with the coordinator.
- `cold_rmw` counts base reads from the store only (a partial write over a hole needs no read).

## Decisions taken (lead to confirm)

1. `destage_cut` borrows the cut (plan wrote it by value).
2. The last segment is left open for the caller's C4; full ones are sealed inside the cut. M11 must call `seal_open` and `insert_into_index`, and must not insert on a failed commit.
3. The job queue is the list of job descriptors of the whole cut (cheap), bounded in memory by `result_window` instead; "depth" is jobs not yet started.
4. `MapFull` fails the whole cut (nothing applied); the caller seals the map and cuts again, wasting the stored extents (orphans). A cut that needs more dirty leaves than the cap is not split.
5. `Closed` is returned for cancellation; a failure that stopped the pool is reported as itself.
6. Base-read stale-hint fallback is implemented here as well as in the engine read path.
