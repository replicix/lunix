## Semantics fixed here

- API: `destage_cut(&OverlayCut, &DestageDeps) -> Result<DestageOutcome, DestageError>`. The cut is borrowed (the caller needs it for `Overlay::release`).
- Workers run assemble, scan, id, dedup, compress, seal on jobs of `min(16, 1 MiB / chunk)` chunks. The calling thread packs in chunk order and applies one `MapTxn` at the end, so a failure applies nothing to the map.
- **Determinism:** a chunk equal to an earlier one in the same cut is resolved in order (first in LBA order is stored, the rest point at it). A worker that reaches an id already claimed skips compression; the packer takes the sealed extent from the claimer's slot. Layout is independent of thread timing (test over 1, 2, 3, 8 workers).
- **Segments:** superseded by the review fixes below: every segment is sealed before the map commit.
- **Dedup:** `get_for_dedup`; `Verified` taken as is; `Hinted` confirmed by reading the extent with `OpenExpect.chunk_id = Some(full id)` (all 32 bytes plus tag/AEAD through the codec). Any data error (NotFound, Corrupt, Auth, Unsupported) or an absurd hint (`clen` 0 or above the chunk size, not read at all) is a miss. Host `Io` propagates.
- **R1:** the base read passes the leaf prefix, the confirmation read the full id, both the chunk size. A stale or wrong hint falls back to `get_by_prefix`, each candidate confirmed against its full id; with no candidate the original `Auth` stands. A lean map (`id_len` 0) has no fallback.
- **Compression:** `auto` = LZ4 probe of the first 4096 bytes, raw if `saved * 100 < 6 * probe_len`, else zstd at the policy level; any codec output not smaller than the input is stored raw. Backpressure: the depth is the number of jobs not yet started when a job starts (depends only on the job index, so it is deterministic); above `lz4_depth` use LZ4, above `raw_depth` store raw. Defaults 4096 and 16384 jobs.
- Space: destage returns `ReadOnly` if the gate is read-only and calls `fatal_io` on a host `EIO`. The ledger reservations (C2 headroom, C4 true-up) stay with the coordinator.
- `cold_rmw` counts base reads from the store only (a partial write over a hole needs no read).

## Review fixes

Review verdict was "merge after fixes" (`01-p1-m9-review.md`). Lead decisions applied:

1. **Blocker 1, map committed while the last segment was `.open`.** Every segment is now sealed before `txn.commit()`. `DestageOutcome::open` and `seal_open` are gone; `DestagedSegment::sealed` is a plain `SealedSegment`. The rustdoc claim about the overlay is removed. New crash point `destage.after_segment_seal`. `insert_into_index()` is for after the commit that names the segments is durable. Test `every_map_entry_is_readable_the_moment_the_cut_returns` reads an untouched block of a partially overwritten chunk and every map entry through the store right after the cut returns (fails if the final seal is moved after the commit).
2. **Major 2, oversized cut.** Before any extent is stored, `probe_map` opens a transaction, `set_hole`s every chunk of the cut and drops it. `MapFull` then costs nothing (`partial.segments` empty, no `segment.append` hit). New `ErrorClass::CutTooLarge`: `MapFull` with `dirty_leaf_count() == 0`, so sealing cannot help; the coordinator must bound distinct leaves per cut. `MapFull` with dirty leaves is `AfterMapSeal`. Tests: `map_full_is_found_before_anything_is_stored` (a cap-at-`set` map wrapper), `a_commit_time_map_full_deletes_what_the_cut_stored`, `a_map_with_dirty_leaves_asks_for_a_seal_not_a_smaller_cut`.
3. **Major 3, orphans.** On any failure after segments were sealed, the cut deletes them (`SegmentStore::delete`, best effort) and reports `Partial::segments` and `Partial::freed_bytes`. A crash leaves them to the sweep or GC (rustdoc). Note for the lead: the store trait calls `delete` "GC only"; the sentence should be widened.
4. **Major 4, error contract.** `DestageError { error, class: ErrorClass, chunk: Option<u64>, partial }`. Classes: `Transient`, `AfterSpace`, `AfterMapSeal`, `CutTooLarge`, `Permanent` (Auth, Corrupt, Format, NotFound, Invalid, Unsupported, Refused, AlreadyExists), `Stop` (ReadOnly, Closed, host EIO/EROFS). The table is in the `ErrorClass` rustdoc; `is_retryable()` is true for the first three. `fatal_io` is now called for EROFS as well as EIO (nit 12). The failing chunk is carried from the worker (base read, seal) and the packer.
5. **Minors.**
   - Determinism under backpressure and pressure signal (5, 6): the job-position depth is gone. Pressure is one `Pressure` level (`None`, `Lz4`, `Raw`) per cut: `DestageConfig::pressure` (set by the coordinator from journal fill or the ladder) combined with byte thresholds on the cut size (`lz4_cut_bytes` 4 GiB, `raw_cut_bytes` 16 GiB by default, chunk-size independent). The stored codec cannot depend on which job claims a duplicate. Test `the_layout_under_pressure_does_not_depend_on_which_job_claims_a_duplicate` (batch 1, 1 to 8 workers).
   - Lean volumes (7): the base read sets `verify_id` when `id_len` is 0. Test `a_lean_volume_reads_its_base_as_a_scan`.
   - `write_seq` (8): `check_pieces` refuses a data piece with `write_seq` 0 or above `cut_seq` (`Invalid`, `Permanent`). Test `a_piece_above_the_cut_is_refused`. `check_cut` also refuses chunks beyond the map.
   - Verified adopt (9): a hint with `clen` 0 or above the chunk size is treated as a miss (counted in `dedup_rejected`).
   - Panics (10): `# Panics` on `destage_cut` (a worker panic propagates after the pool stops; the coordinator decides to catch or abort).
   - Also: `result_window >= workers` validated (recommendation 3), `debug_assert` in `codec_slot` (nit 16), R1/`plain` sentence in `lib.rs` (nit 15). `writes` follows on-disk-formats item 27 (nit 18).
6. **Test gaps (11):** (a) done, (b) done, (c) done with `batch_chunks = 1`, (d) the model test now has a 40-chunk family with 1 to 4 workers and batches of 1, 2 or 16 (many jobs, window, several segments), (e) comment not added; the clen guard is codec independent.

Deferred: nits 13 (reuse the compression output buffer at its bound) and 14 (slot slab); a pressure input from the real journal fill is the coordinator's to set; the quiet-host, 8-core re-run of the throughput gate (the reviewer's request) needs a host this milestone does not have.

New API shape: `destage_cut(&OverlayCut, &DestageDeps) -> Result<DestageOutcome, DestageError>`; `DestageOutcome { cut_seq, segments: Vec<DestagedSegment> (all sealed), map, stats }` with `insert_into_index(&dyn ChunkIndex)` and `sealed_bytes()`; `DestageError { error, class, chunk, partial: Box<Partial { segments, freed_bytes, stats }> }`; `DestageConfig` has `pressure`, `lz4_cut_bytes`, `raw_cut_bytes` instead of the depth fields.
