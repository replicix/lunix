## Wording for the plan, DESIGN and DECISIONS

1. **QUIESCE is not "idle".** Plan step 6 and DESIGN §3 "Planned upgrade", ADR-16: "`QUIESCE_DEV` returns once every queue
   has an idle command; requests the server already holds stay with it. The daemon completes and commits those with
   commands of its own (libublk would drop them), waits until its queue threads have ended with nothing in flight, runs the
   engine's final commit, then exits; no `STOP_DEV`, no `DEL_DEV`. The kernel has seen every commit, so the successor has
   nothing to replay. A request the daemon cannot commit is left for `REISSUE` (only by `abort()`)."
   ADR-16 "never exits while started requests are not being completed" then has exactly one sanctioned exception:
   `abort()` (recoverable like `kill -9`).
2. **libublk, ADR-18 gaps:** "libublk 0.4.8 assumes handlers complete at once: after the first `ABORT` it queues no commit and
   ends its loop; a completion in the same batch as the first `ABORT` keeps its in-flight count above zero for ever. The
   layer keeps its own queue-down flag (set by an `ABORT`, or by the control side after `QUIESCE_DEV` or `TRY_STOP_DEV`: a
   queue whose tags are all held gets no `ABORT`), commits held requests itself and never blocks in libublk once down."
3. **A failed `QUIESCE_DEV` is not a no-op** (plan step 6): "On `EBUSY`/`EINTR` the device stays canceling: new I/O is
   requeued, not served. The caller retries `quiesce` or calls `crash_for_recovery()` (abort, recovered by `REISSUE`); it
   never detaches or deletes the device in this state (the device is latched `Quiescing`)."
4. **`TRY_STOP_DEV`** (plan step 7, DESIGN "Detach"): "answers `EBUSY` while the block device has any opener: a mount, an open
   descriptor, or udev's probe just after the device appeared. Detach of a new device retries for a bounded time."
5. **`UPDATE_SIZE`** (plan step 8): "is sent only to a device that has a disk (state not DEAD); older drivers dereference a null
   disk."
6. **Identity** (plan step 5, DESIGN §3): "ublk has no owner concept; the daemon stores a volume tag in `ublksrv_flags` and
   checks it. A device is recovered only if the boot id and volume equal the record's, the state is QUIESCED, or LIVE with no
   living server, the volume tag, queue count, depth, buffer size and flags match, and `record.dev_sectors <= dev_sectors <=` the
   engine's size (a grow makes the engine durable, then the kernel, then the record; a crash between any two leaves them in
   this order). The recovered device is re-checked after `START_USER_RECOVERY`."
7. **New rule next to W1:** "**`DEL_DEV` of a LIVE device is a `STOP_DEV`.** It is sent only after a successful `TRY_STOP_DEV`,
   or by another process for a device without a server. Never by the serving process as a fallback." (`delete_by_id` refuses a
   LIVE device unless forced.)
8. **Attach order** (DESIGN §3 / M12): "The record is written between `SET_PARAMS` and `START_DEV` (`add_persisting`); a device
   that was added and never started is DEAD and harmless."

## What M12 must call

`UblkDevice::add_persisting` (first start, with the record writer), `UblkDevice::recover` (later starts; on
`UblkError::Identity` add a new device), `record()` after every grow, `quiesce_and_exit` for an upgrade, `detach` for a stop
(retry on `Busy` for a bounded time), `harden_process` first. Handle `UblkError::Device { dev_id, .. }` (record the id; another
process deletes the device with `delete_by_id(.., true)` once the daemon is gone) and `warnings()`. libublk prints
`device reload json failed` once per attach; it is harmless. Persisting the record after an engine-initiated grow through the
resize hook is the daemon's job.

## History in short

First root run: five daemonless devices left by test failures (test bugs), cleaned up by the lead; the QUIESCE exit path
aborted its own safety check and led to the first own loop; a crash-point script bug left one device stuck (fio in `D`
state) and was cleaned up by the lead; the host was stopped once. All of these are fixed (`LUNIX_CRASH_AT` reaches only the
daemon meant to crash, `rescue.sh`, every failure path recovers a daemon before it unmounts, no delete of a live device).

## Deviations

- fio ignores `--io_size` with `--time_based`; crash-loop jobs are bounded by `--runtime` and a fixed 1 GiB per-job working
  set. Bounded cells (raw verify, resize) use `--io_size`.
- `DEL_DEV` runs inside the control watchdog (60 s) instead of a separate helper thread.
- Root scripts call their own `df_guard` before each `mkfs`; the driver also calls `remote.sh df-guard` before every run.
- `sudo` clears the environment: scripts get `LUNIX_SPIKE_DIR`, `TESTD`, `LUNIX_ROOT_TESTS` through `env`.
- Resize cells moved far less than `--io_size 2g` per job (slow shared disk); the grow happens under load 8 s after fio starts.
