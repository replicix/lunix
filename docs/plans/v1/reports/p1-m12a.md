**Memory (decision 2): allocator tuning and idle trimming.**
- At start, before any thread: `mallopt(M_MMAP_THRESHOLD, 128 KiB)` and `mallopt(M_ARENA_MAX, 4)`.
  - glibc's dynamic threshold is the cause of the retention: after the first large free, the chunk buffers move to
    the heap and stay there.
  - Under `mlockall` the kernel ignores `madvise(MADV_DONTNEED)` on locked pages, so `malloc_trim` alone cannot
    give that memory back.
  - With a fixed threshold, every buffer of 128 KiB or more is `munmap`ed on free, which unlocks it.
- `lunixd-trim` thread: once every volume has been idle for `idle_trim_ms` (default 10 s), it calls
  `malloc_trim(0)` once. Activity re-arms it, and it never runs on a queue thread.
- `lib.rs` is now `#![deny(unsafe_code)]`. `trim.rs` allows unsafe for the two libc calls, each with a SAFETY
  comment.
- The gate needs ublk, so it needs root, and is listed for the old host. With `device = "none"` there is no
  locked buffer and no I/O path through the daemon, so a no-root reading would not be the gate's figure.
- `m12a-smoke.sh` now measures the gate after the smoke and crash cells, on the same daemon. The fresh-daemon
  reading is printed for information.

### Torn tail under `refuse` (review "needs a run" 6): found, then decided and fixed

**Finding.** When the last record of a lane is torn and nothing valid follows it:
- the journal reports a damaged range with `next_seq: None`;
- the engine refused on any damaged range;
- so `on_journal_damage = refuse` kept a volume offline after an ordinary crash.

**Lead decision of 2026-11-13** (implemented on `lead/p1-iface2`, `0eace35`): `refuse` refuses only mid-journal
damage, meaning either of:
- a damaged range with a later valid record in its lane (`next_seq` set);
- `ignored_after_gap`.

A torn last record of a lane is crash residue: it is logged at warn and wiped. The argument is in the engine's
rustdoc (`refuse_worthy`, `OnJournalDamage::Refuse`), in ADR-4, in DESIGN §4.1 and §4.4 step 7, and in the plan:
- a FLUSH or FUA completes only after the group flush covering it has `fdatasync`ed the lane file;
- so an acknowledged-durable record is on stable storage before its acknowledgement and cannot be torn;
- a torn tail can only hold a write that was never flushed, which block semantics allow to lose.

**Tests:**
- Engine unit test `only_mid_journal_damage_is_refused`.
- lunixd `wiring::a_torn_last_record_is_crash_residue_under_refuse`: opens, the tail is reported and logged, the
  earlier records are there, the torn write is gone.
- lunixd `wiring::damage_followed_by_a_valid_record_is_refused`: refused, journal byte-identical.
- The existing gap test still refuses.

## Checks the brief asked for

- **`chain_floor` and ADR-31 "written after every verified attach, incl. the EPOCH commit".** No mismatch in phase 1.
  A local-only attach writes no EPOCH commit (epoch 0, no lease, DESIGN §13.3). The engine raises the floor to the
  verified tip at open (`engine.recover.floor`) and after every C6. Two problems will appear in phase 2:
  - `chain_floor = max(parent.chain_floor, seq - (retain_last - 1))` assumes that every commit is a FULL. With
    EPOCH or CONFIG commits in the chain, it keeps fewer than N FULLs and can name a non-FULL commit as the floor.
    The rule is "the oldest of the last N FULLs".
  - Recovery raises the floor before an attach-time EPOCH commit exists. Phase 2 must raise it again after that
    commit is durable (on-disk-formats §20 says so).
- **Fork above the floor (engine gap).** The engine returns `Fork` only when the tip is exactly at the floor's
  height. On-disk-formats §20 also asks for a check when the tip is higher: the commit at `max_commit_seq`, if it
  is still at or above the tip's `chain_floor`, must hash to `tip_hash`. Without that check, a forked chain one
  commit past the floor attaches and raises the floor.
  - Until the engine changes, `stack::precheck_fork` makes this check before `Engine::open`, so nothing is written.
    Test: `wiring rollback_and_fork_*`, the fork at tip 4.
  - Proposed engine diff, in `recover.rs` after the existing R4 block (the chain is verified at that point):
    ```rust
    if let Some(f) = &floor {
        if f.max_commit_seq < tip_seq && f.max_commit_seq >= tip.chain_floor {
            let bytes = d.commits.get(f.max_commit_seq)?;
            if d.commit_codec.object_hash(&bytes) != f.tip_hash {
                return Err(OpenError::Fork { tip: f.max_commit_seq });
            }
        }
    }
    ```
- **Minor 8.** `cfg.map_fanout` is set from the descriptor (fanout-256 test).
- **Minor 9.** Handlers are dropped only after a drain: the ublk layer's own drain, and nothing is in flight on the
  null device.
- **Journal reclaim after open.** `commit_now(false)` runs once after the lanes are open, when records were replayed.
- **Minor 7** (`bound_cut` vs `dirty_leaf_count`) is the engine's. It is not reachable with the defaults, and I left
  it alone.

## Decisions taken where the plan was silent (lead to confirm)

1. **Which kind of credential the request is.** `ctl::Credential` cannot say whether the caller expects an encrypted
   or an integrity volume.
   - A passphrase or key file is an **encryption** credential, unless this host's pin (recorded at create or first
     attach) says `integrity`. In that case it is an integrity credential.
   - With no credential, an integrity volume is unlocked with its own `integrity.key` (D16).
   - Effect: an integrity volume with a passphrase slot attaches on a host with its pin, and gets `Downgrade` on a
     host without one, until iface gap D lands.
2. **Pins.** The daemon is the pin store. It writes the pin and `keyring_seq` at create, passes the pin and
   `max_keyring_seq` to `check_attach`, and records an absent pin after R4 has passed.
3. **Error codes.** The mapping, as no code exists for most of these:

   | failure | code |
   |---|---|
   | `BadMac`, `KeyringRollback`, `Rollback`, `Fork` | `downgrade` |
   | `NeedCredential`, `ModeMismatch`, `Unsupported` | `invalid` |
   | `WrongCredential` | `wrong_kmk` |
   | journal damage with `refuse` | `io` |
   | `Gc` (no collector in this build) | `invalid` |
   | `GcStatus` | idle default snapshot |

4. **Create.**
   - An encrypted volume needs a passphrase or a key file; the daemon never puts a generated key beside it.
   - An integrity volume with only a passphrase gets a passphrase slot alone.
   - The size must be a multiple of the chunk size.
   - `auto` compression is zstd level 1.
5. **Queues.** In order of precedence:
   - the device record (when recovering);
   - the request;
   - the journal lanes already on disk;
   - the config;
   - `min(8, cpus/4)`.

   Fewer queues than existing journal lanes is `invalid`.
6. **Detached volumes.**
   - `Space` edits `volume.json` directly (no keys needed, no lock).
   - `VolumeList` and `VolumeStatus` show size 0 for an encrypted volume (the size is sealed in its commits).
7. **`QuiesceAll`.** On success it leaves every volume mutex locked and exits: code 0, or 70 when a final commit
   failed. On a quiesce failure the daemon keeps serving and logs.
8. **Per-call timeout.** After the timeout the caller gets an `internal` reply. The call keeps running, and the
   volume mutex serialises the next call.
9. **Test-only surface.**
   - `device = "none"` with the `null-device-busy` marker file.
   - `lunixd ctl` and `lunixd check` stand in for M13a and M14.
10. **Smoke parameters.**
    - The device symlink goes to `<scratch>/…/dev/<name>`, not `/dev/lunix`.
    - `journal_max` is 512 MiB (it must be ≥ lanes × 2 × 64 MiB).
    - The crash cell's randwrite is rate-limited, because there is no GC yet and the disk budget is small.
