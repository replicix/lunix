## Decisions taken where the plan was silent (lead to confirm)

1. **Construction is inherent, not in the trait.** `LocalVolume::create(dir, volume_bytes, &VolumeJson, Arc<dyn MetaCodec>, StoreOptions)` and
   `LocalVolume::open(dir, Arc<dyn MetaCodec>, StoreOptions)`. The codec is needed up front for footers, pins and evidence, so a caller reads
   the descriptor with `read_volume_file(dir)` (no lock), derives keys, then opens. `create` writes `volume.json` first and `volume` last; a
   crash in between leaves a directory that does not open as a volume, and a second `create` finishes the job.
2. **Stale-lock takeover is flock itself.** The kernel drops a flock when its holder dies, so `kill -9` leaves a free lock; no `/proc`
   classification (Constellation ADR-29) is needed here. `LOCK` carries the holder's pid for humans only.
3. **Checkpoint tail guard.** `CheckpointStore::load` returns the newest valid slot as written (the contract suite requires equality with a
   slot whose commit does not exist). The guard is `LocalVolume::load_checkpoint_hint()` / `tails_usable(slot, tip)`: when
   `last_commit_seq` is above the commit tip the slot comes back with all `lane_tail_ordinals` zero ("skip no file") and `tails_usable =
   false`; `id_high` stays usable. `store` refuses a slot for another volume (`Invalid`); `load` ignores one (warning). `zero()` is an atomic
   replace of an all-zero file, not two slot writes, so a crash cannot leave the older slot valid after `--truncate-tip`.
4. **No logger in the crate.** "Ignored with a warning" is `LocalVolume::take_warnings()`; the daemon logs them (adding `tracing` would be a
   dependency change).
5. **`footer()` does not hash the extent region** (16 MiB per call would make `catch_up` unusable). It authenticates the footer and checks
   tiling and trailer agreement; `verify_segment`/`verify_pack` stream the region against `seg_hash` (for fsck and tests).
6. **`read_extent` checks that the stored `clen` field equals `hint.clen`** besides bounds, so a misaligned hint is `Corrupt` rather than
   random bytes for the codec; the tag stays the codec's single verification.
7. **Unsealed writers.** A dropped writer unlinks its `.open` file at once; the open-time sweep covers the crash case. An empty writer cannot be
   sealed (`Invalid`; the format needs at least one extent).
8. **Descriptor cache** of sealed containers: 256 by default, oldest evicted; an `ExtentLocation` keeps its fd through eviction and delete.
9. **`FsOps` is public** (the five durability calls) as the test seam; `StoreOptions` has `allow_tmpfs` (default from
   `LUNIX_ALLOW_TMPFS_FOR_TESTS`), `segment_target` (16 MiB) and `max_open_files`.
10. **Leftover scan** covers the whole volume directory except `cache/`; `.damaged` files from `set_aside` are never touched.
11. **Pins** are read-only here; an undecodable pin, a pin under a wrong name, or a file with an invalid name is an error. `*.tmp` is skipped.
12. **Crash tests need `--features crashpoints`** (superseded by the review round, below): `lunix-store` has its own feature
    `crashpoints = ["lunix-iface/crashpoints"]`; the sweep tests are `#[cfg(feature = "crashpoints")]`. The lead adds
    `cargo clippy/test -p lunix-store --features crashpoints` to `ci.sh` after the merge.

## Spec gaps found

- `Hint.clen` is the payload length but `NodeLoc.len` is the whole extent length (the iface docs say so); `read_node` derives `clen = len -
  OVH`. Worth one sentence in the formats doc.
- The plan's M7 step 7 lists `delete_run`; `lunix-iface` has no run store (M6 owns `index/` files). The store only creates `index/` and counts
  its ids; `LocalVolume::index_run_path` was not added. M6 deletes its own runs (with its own durable order).

## rust-skills conflicts / notes

- `err-no-unwrap-prod`, `anti-unwrap-abuse`: only the test modules use `expect`/`unwrap` (assertions); the library code has none on disk or caller data.
- `api-non-exhaustive`: `StoreOptions` has public fields and no `#[non_exhaustive]` so tests and callers can use struct update; no semver
  promise exists inside the workspace.
- `doc-all-public`: public items documented; internal `pub(crate)` helpers carry short intent comments only.
- `unsafe-*`: no `unsafe` in the crate (rustix and `platform-lite` carry the syscalls).
- `async-tokio-fs`: n/a, the store is blocking by contract.

## Skipped / deferred

- `fallocate` of large segment files (plan: "may use"): not done; appends are buffered (1 MiB) and the space gate (M8) reserves the 16 MiB.
- The `link`+`unlink` fallback of the create-only rename (file systems without `RENAME_NOREPLACE`) is written but not exercised: the host's file
  system supports the flag.
- Power-loss behaviour (as opposed to process kill) is out of reach of this suite; the crash tests assert the order of calls
  (`fsync accounting`), not device-level durability (stretch item in M15).
- Footer cache: none; `footer()` re-reads and re-authenticates each call.
