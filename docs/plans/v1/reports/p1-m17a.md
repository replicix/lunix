## What was built (`crates/lunix-gc`)

`Gc` implements `lunix_iface::gc::Collector` (dependencies unchanged: format, iface, thiserror, tracing; testkit,
lunix-map and proptest as dev-dependencies). A `crashpoints` feature forwards to `lunix-iface/crashpoints` (no
normal edge enables it). Public API besides the trait: `Gc::new(floor, GcConfig)`, `Gc::with_hooks`,
`Gc::status()` (a `GcStatusSnapshot` for M12's `GcControl`), `Gc::totals()`, `liveness(view, cfg)` (the read-only
mark fsck/M17.B compares with), `CondemnedList` (decodes `state/gc/condemned`), `FloorSource`, `GcHooks`,
`CRASH_POINTS`, `compact::{candidates, rank, Candidate}`.

| module | content |
|---|---|
| `mark.rs` | Root set pinned at mark start (retained FULLs, then pinned commits read and opened through the commit codec; an unreadable pin fails the pass) and object listings taken at the same moment (only listed objects are candidates). A **full** `walk_nodes` per root for pack liveness (M5 note); leaves walked with `walk_leaves_skipping`, skipping every node hash an earlier root reported, in at most 64 batches per root (the other leaves of the root go in the skip set). Resolution against the **authenticated footer** (R3) at exact `(off, clen)` with the entry's prefix; else `get_by_prefix` with each candidate confirmed against its footer (stale hint). The live copy of an id is the index's current copy confirmed against its footer, else the hinted extent; lean volumes keep every hinted extent. `deps`: for a segment hints point into while the live copy is elsewhere, the highest such copy segment (delete-time index invariant). The live set is a sorted `Vec<LiveExtent>` (hint + first chunk number, 24 bytes). |
| `collector.rs` | The pass: `Marking → Condemning → Grace → Rechecking → Deleting → Compacting → Finishing`, each a sequence of units; `step` runs units until the budget is spent. Condemn writes the list first (`gc.condemn.after_list_write`), then flags each segment in the index; graces start when all flags are set. Recheck = a new mark pinned after the grace; verdicts delete / un-condemn / gone / defer. Delete re-judges each object against the view of its own step, applies the delete-time invariant, then unlink → `drop_segment` + unflag → ledger `release`. Commit objects: below the durable tip's `chain_floor`, below the rollback floor, not pinned. The urgent pass, the dry run, statistics, evidence. |
| `compact.rs` | Candidates (`u < threshold`, at or below the high-water mark, not condemned, not an unnamed output, not introduced by the tip FULL), LFS cost-benefit ranking with age = high-water mark minus id, up to 1 GiB live per pass, copy in chunk-number order, re-seal through `ExtentCodec::seal`, one output open at a time charged from headroom, `relocate` only after the seal, moves pushed one by one into an outbox kept across failed steps. |
| `condemned.rs`, `evidence.rs` | The `state/gc/condemned` body (version 1) and the `gc/<pass>` JSON lines, both defined in `docs/reference/gc.md`. |
| `config.rs`, `points.rs`, `footers.rs` | `FloorSource` (blanket impl for every `VolumeDir`), `GcHooks`, `GcConfig`, the grace-floor check; the crash points; a 32-entry LRU of decoded footers. |
| `docs/reference/gc.md` | Roots, liveness, the four-step delete, mark staleness, compaction, settings, both file formats, crash points, ledger, what the wiring must do. |

### The rollback-floor requirement (maintainer, 2026-11-13)

`GcView` does not carry the floor and the interface is frozen, so the floor comes from a constructor argument:
`Gc::new(floor: Arc<dyn FloorSource>, ..)`, where `FloorSource` has a blanket implementation for every
`VolumeDir` (the wiring passes the volume directory; there is deliberately no "no floor" implementation). Every
condemn, recheck and delete of a commit object reads the floor; a commit with `commit_seq >= max_commit_seq` is
kept, also below `chain_floor`; an unreadable `state/pins` keeps every commit object for that pass (fail closed).
Only the commit objects are kept: their map roots are not GC roots. Tests:

- `scenarios::the_rollback_floor_window_keeps_commits_below_chain_floor`: the floor stalls at 3 while 12 more
  FULLs and passes move `chain_floor` past it; afterwards exactly the commits `>= 3` exist, `verify_chain(tip, 3)`
  (the attach walk) succeeds and the floor's `tip_hash` matches; once the floor is raised again, the window closes
  and the commits below `chain_floor` go.
- `scenarios::an_unreadable_rollback_floor_deletes_no_commit`: a failing `FloorSource`, 10 passes, every commit
  object still there while segments and packs are collected.
- The oracle's `FloorStall` operation and `check_commits` (every commit from `min(chain_floor, floor)` to the tip
  must exist after every pass; at quiescence the commit set must equal it plus pins).
- Mutation check: removing the floor condition fails 6 tests (the five oracles and the scenario).

## Decisions taken (the lead confirms)

1. **The floor comes through the constructor** (`FloorSource`), not the view; see above.
2. **Unnamed compaction outputs are tracked by the collector**, not only by the high-water-mark rule. A cut can
   lift the mark above an output before a FULL names it (the moves are applied at the next cut, but a step on an
   idle volume, or a lagging wiring, leaves a window), so the mark rule alone would let a dead output be deleted
   and then named by the FULL that applies the moves. At each step the collector reads the FULLs committed since
   its previous step (a commit object exists only once durable, and GC deletes none it has not read), and an
   output one of them names is no longer pending. An output whose relocations all failed gets no move, so no cut
   names it: it is an ordinary orphan.
3. **The delete-time index invariant is enforced, not only argued**: a segment that hints point into while the
   live copy is elsewhere is deleted only when that copy's segment is at or below `named_high` (the highest id any
   FULL read as above names) and not an unnamed output; otherwise the delete is deferred. The first version used
   the tip's high-water mark; the 2 000-sequence gate run found a volume that never converged with it (a FULL
   that named the copy rolled off and the mark fell below it, so the source was deferred forever; safe, but a
   leak). `scenarios::a_copy_named_by_a_full_that_rolled_off_before_any_step_still_counts_as_durable` pins it.
4. **Moves are never lost**: a step that fails after relocations keeps the moves in an outbox and returns them
   with the next successful step or urgent pass.
5. **Grace clock**: the list's `condemned_at` is informational; the grace runs on the monotonic clock of the
   process and restarts when the list is loaded after a restart (a restart never shortens it). The urgent pass
   uses the floor grace with its own mark as the recheck.
6. **Index flags and the list are reconciled at every pass start and load**: a listed segment without a flag is
   flagged with a fresh grace (closing the window where dedup could reach a listed segment after a crash between
   the list write and the flags); a flagged segment that is not listed is adopted (fresh grace) or unflagged when
   it is gone. Deleted segments are unflagged after `drop_segment` (the real index keeps the flag otherwise).
7. **A pass that changes nothing writes no evidence object** and its number is reused; evidence beyond 48 MiB is
   counted, not kept (a `truncated` line).
8. **When a pass is due**: 30 s after the previous one (`GcConfig::pass_interval`), and only with a new tip, a
   non-empty list or changed pins.
9. **Reader pin deadlines are ignored** in phase 1 (a lapsed reader pin is still a root): conservative, and there
   are no reader pins yet.
10. **Live bytes are `clen` sums; `u = live / file size`; age = high-water mark minus the segment id** (ids are
    monotonic; the commit that named an old segment may be gone). The minimum age of one commit interval is "not
    introduced by the tip FULL".
11. **`GcPassSummary::bytes_moved` is the live bytes of the compacted sources** (the dry run reports the same
    measure); `GcStats::compaction_read/written` count extent and file bytes.
12. **Crash sweep in-process**: the plan asks for a child process, but the fakes are in memory, so a child's state
    would die with it. As in M11's model test, each point is a `crashpoint!` (SIGKILL in the `crashpoints` build)
    plus `GcHooks::crash_at`, and the fakes' crash images are what a kill leaves. The real-stack kill loop is
    M17.B's.
13. **Encrypted re-seal**: the testkit has no encrypting codec and `lunix-crypto` is not a dependency of this
    crate, so the salt test uses a test-only codec with the encrypted layout (`OVH` 108, a fresh salt per seal);
    the real-codec run belongs to M17.B (the plan's "tripwire build").

## Requests to the lead

1. **Engine defect, `coord.rs` `true_up_index` (M12 / M11 follow-up).** The engine keeps a private
   `index_charged` and at each commit releases `index_charged - total(all_runs)` when the run bytes shrank. GC
   releases the bytes of each index run it deletes (iface `space` walk-through step 6), so the engine releases
   them a second time at the next commit and the `Index` charge drifts low by the run's bytes. Reproduce: a run deleted by GC (any run neither the manifest nor a retained FULL
   names), then one commit; `snapshot().by_kind[Index]` is below the run bytes. Fix: true up against the ledger
   (`transfer(Index, Index, snapshot.by_kind[Index], total)`) instead of the private counter, or have GC not
   release `Index` (then the ledger over-counts until the next commit). GC follows the walk-through as written.
2. **Wiring (M12).** `Gc::new` needs the volume directory as `FloorSource`; `GcControl::run_urgent` must hand
   `GcProgress::moved` of the urgent pass to the next cut like a step's (the engine's `gc_step` does this for
   steps only); `GcControl::status` can return `Gc::status()`.
3. **Optional iface additions** (not needed for M17.A): `GcView::rollback_floor` would make decision 1
   unnecessary; `GcStateStore::delete_evidence(pass)` so old `gc/` objects can be pruned (today they accumulate,
   one per pass that did something, and are outside the ledger, like the engine's startup accounting).
4. **ci.sh**: a `lunix-gc with crashpoints` line (`cargo clippy -p lunix-gc --all-targets --features crashpoints`)
   like the other crates'; it passes on this branch.

## Spec gaps found

- **N10 (new): the high-water-mark rule does not cover every unnamed compaction output** (decision 2): an output
  can fall below the mark before the FULL that names it exists. Proposed text for rule 7: "nor a compaction output
  whose moves no durable FULL has applied yet".
- **N11 (new): `chain_floor` vs the rollback floor and the attach walk.** With the floor raised after every FULL
  the window is normally one commit; it widens only when a raise fails or a host attaches with an old floor. GC
  keeps those commits as chain links but not their data; this is what ADR-31 needs (the walk authenticates links
  only) and is now in `gc.md`.
