## What was built (`crates/lunix-map`)

| file | content |
|---|---|
| `src/map.rs` | `RadixMap`: `BlockMap` over `lunix-format` nodes (fanout 256/512, levels from the size, `E_L` empty hashes, raw interior nodes, hashes over child hashes and level only), lazy `open(root, chunk_count)`, resident interior nodes, `seal` (path copy, one pack), `grow` (wrapper nodes created at the next seal), `walk_leaves[_skipping]`, `walk_nodes[_skipping]` over any root, `warm_interior`, `cache_stats` |
| `src/txn.rs` | `MapTxn`: buffered ops, `rehint` evaluated at commit, dirty-leaf cap (`MapFull` from `set`/`begin_update`), no-op transactions dirty nothing |
| `src/lru.rs` | encoded-leaf cache (byte-bounded LRU keyed by node hash, hash-prefix hasher) with a decoded tier for hot leaves |
| `src/fastleaf.rs` | point-lookup reader for `rb16` leaves (see decision 2) |
| `src/config.rs` | `MapConfig`: `map_fanout`, `id_len`, `map_cache_max` (256 MiB), `dirty_leaf_cap` (20 000), decoded tier size (256 leaves) |
| `tests/` | contract, model, roots, corruption, tamper, walks, cache, perf (ignored) |

Locking: one state mutex held only for short, I/O-free sections (so `try_get_cached` never waits for I/O or for a
seal) plus a writer mutex serialising commit, seal and grow. A seal snapshots the dirty leaves (still visible to
readers), works without the state lock, and swaps root and overlay at the end.

R2 (M2 security review, from the lead): every node load opens the extent (kind Node), requires codec 0 and
header `chunk_id` == the parent's `child_hash` (the commit's root hash for the root), and recomputes the hash from
the decoded content (leaf: whole encoding; interior: header and child hashes) and compares it. Test `tamper.rs`
swaps every node of a two-version tree for an older-pack node of the same level and for a sibling from the same
pack, and serves a codec 1 extent with a valid id and tag: all refused.

## Decisions taken

1. **Hashing goes through `ExtentCodec::chunk_id(Node, ..)`** for leaves and interiors (keyed hash in encrypted mode),
   not `blake3` directly; the `blake3` dependency is used by the tests' codec only.
2. **A private point-lookup reader (`fastleaf.rs`).** `LeafView::get` measured 281-290 ns by itself (about 70 bit-field
   reads, each a byte loop over a `u128`), so no cache layer could meet the 250 ns gate. `fastleaf.rs` reads the same
   bytes with one unaligned 64-bit load per field and fewer reads, and is tested against `LeafView` and `Leaf::decode`
   on random valid leaves and on damaged bytes (400 + 400 proptest cases, same answers, same accept/reject). The leaf
   is still validated by `LeafView::parse` and the hash check at load, and strictly by `Leaf::decode` in walks. If you
   prefer one reader, the equivalent fix in `lunix_format::node` is an 8-byte-load fast path in `get_bits`, a
   start-only read in the run binary search and a same-group shortcut in `s_of`; then `fastleaf.rs` can be deleted.
3. **Decoded leaves are 32 KiB at fanout 512, not 24 KiB** (`size_of::<Entry>()` is 64 bytes because `IdPrefix`
   holds 32 bytes). The default cap of 20 000 dirty leaves is 640 MiB at 512; the report numbers above do not include
   an overlay. The cap is configurable.
4. **Cap accounting is conservative:** a `set`, `set_hole` or `rehint` counts its leaf at call time whether or not it
   changes anything; commit re-checks. `begin_update` returns `MapFull` when dirty leaves >= cap (the trait text).
5. **`open` is lazy and takes `chunk_count`.** A stored root is assumed to have the full depth of that size and is
   verified when first read; an empty root must equal `E_k` for some `k < levels` (so a root sealed before a deepening
   grow still opens). Walks take the root's level from the node itself.
6. **Entries are validated at `set`** (lineage 0, `id_len` of the map, `clen` 1..=1 MiB) so a seal cannot fail on an
   entry.
7. **Seal inserts the leaves it writes into the cache** (bounded by the budget) and retires replaced interior nodes
   from the resident set.
8. **Perf rows use a virtual 10 TiB volume** (as the spike did) with a test-side bulk builder; its interior nodes are real
   and everything is hash-verified like any other node.
9. **Test host**: the "chunk size" of the proptest is a parameter of the volume size (chunk count), since the map only
   sees chunk numbers.

## Requests to the lead

- None blocking. Optional: the `LeafView` speed-up above in `lunix-format` (then drop `fastleaf.rs`).
- **GC/fsck note (M17, M14):** `walk_nodes_skipping` skips by node hash. Two roots can hold the same node content at
  two locations (different packs); skipping then hides the second location. For pack liveness use a full `walk_nodes`
  of each live root, and use the skipping variants for diffs and for leaf marking only.

## Spec gaps found

- The plan says a decoded dirty leaf costs 24 KiB; it is 32 KiB with 32-byte-capable `IdPrefix` (decision 3).
- `walk_*` of a root needs no size, but `open` needs the commit's `size`; M11 must pass it (the commit has it).

## Skipped or not run

- Gates 2-4 of the spike at fanout 256 were not part of this gate. The perf rows ran at fanout 512 only. The proptest and
  root tests cover both fanouts.
- The perf test is `#[ignore]`d (needs release mode and about 60 s); it was run once for these numbers, then again after R2.

## Deferred

- Concurrent seal and commit are serialised by design (single writer); no parallel hashing in seal (34 ms at D = 1 000
  does not need it).

## rust-skills conflicts

- `err-no-unwrap-prod`/`unsafe-*`: no `unwrap` in library code, `#![forbid(unsafe_code)]`.
- `api-must-use` etc. not applied to config setters beyond `#[must_use]`.
- `own-borrow-over-clone`: `Interior::children.clone()` per rebuilt node and one 32 KiB copy per transaction-loaded
  clean leaf are deliberate (copy-on-write).
- No conflicts with CONVENTIONS or the plan other than the commit rule (the implementer rules require signed commits).
