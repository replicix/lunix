## What was built

`lunix fsck NAME` (`src/fsck.rs`)
- Finds the volume directory: with `--dir DIR`, by name in `DIR/<uuid>/volume.json` (or `DIR` itself when it is a volume directory; non-uuid directories and unparsable files are skipped as the daemon's registry rebuild does; two volumes with one name are an error). Without `--dir` the daemon is asked (`VolumeList`); a daemon that cannot be reached gives a usage error asking for `--dir`.
- Refuses a volume the daemon reports as attached, recovering or read-only (exit 3, `busy`). An unreachable daemon or an unknown name at the daemon is not an answer: the library takes the volume `LOCK` and reports `busy` itself.
- Calls `lunix_fsck::check(dir, &Options)` with every flag mapped: `--deep`, `--rebuild-index`, `--repair`, `--gc`, `--truncate-tip`, `--reset-floor`, `--delete-orphans`, `--repair-pins`, `--key-file`, passphrase from the prompt or `--passphrase-fd` (the M13a reader: tty refused, never argv or environment). The `--repair`-only flags are `requires = "repair"` in clap.
- Output: the library's text (plus `hint:` lines) or `--json` (the library's document, with `exit`). Exit code is the library's: 0 clean, 1 warnings only, 2 errors. Hints: `rollback` names `lunix fsck NAME --repair --reset-floor` after restoring the newer state (review A1), `fork`, `tip_auth` names `--truncate-tip`, `credential` says how to give a key.

`lunix key ls|add-slot|rm-slot NAME` (`src/key.rs`)
- Same volume lookup and detached check. Works on `<dir>/families/<family>/keyring` through `lunix-crypto`; a `plain` volume says it has no slots (`ls` exit 0, JSON with an empty list; `add-slot` and `rm-slot` exit 2).
- `ls [--json]`: slot ids, kind (passphrase with Argon2id m/t/p, key file, kms), `keyring_seq`, root kind, `dek_gen`. Read without a credential, so the output says it is not authenticated.
- `add-slot`: new slot from `--passphrase` (prompt, asked twice) or `--passphrase-fd N`, or `--key-file FILE` (an existing file is used; a missing one is generated with mode 0600 and written before the keyring, removed again if the keyring cannot be replaced). Unlock with `--unlock-key-file`, `--unlock-passphrase-fd`, or the volume's own `integrity.key`. Argon2id cost is `Argon2Cost::DEFAULT`.
- `rm-slot --slot N`: checks the slot exists and is not the last before unlocking; prints that the root key is unchanged (ADR-11).
- Both changes: take the volume `LOCK` (flock), unlock, check the unwrapped root against the descriptor MAC (a credential for another volume is exit 6), apply the `lunix-crypto` operation, replace the keyring atomically (temp file with the old mode, fsync, rename, directory fsync), `keyring_seq` rises by one. `state/pins` `max_keyring_seq` is read as the rollback floor for the unlock.
- Errors map to the M13a table: wrong credential, wrong volume or older keyring 6; busy 3; not found 4; bad option mix, unknown or last slot 2; I/O 1.

## Deviations and open choices

1. **Exit code 64 for bad values in `fsck`.** Failures that `lunix fsck` itself detects after parsing (bad name, no `--dir` and no daemon, unreadable passphrase) exit 64, as the `lunix-fsck` binary does, because 2 means "errors found" for this command. clap's own usage errors still exit 2 (`main.rs` is not mine). `lunix key` uses 2 for usage, as the M13a table.
2. **Not recorded in `state/pins`.** A key change raises `keyring_seq` but does not write `max_keyring_seq` to the volume's pins (no store dependency, no iface method); the next attach records it. Until then an old copy of the keyring (with a removed slot restored) is not refused by this host. A sibling volume of the same family sees the new keyring at its next attach.
3. **The keyring is per family**, so `rm-slot` for one volume changes the slots of every volume of the family. Only this volume's `LOCK` is taken.
4. **`ls` is unauthenticated** (no credential is asked); it says so. `fsck` with a credential verifies the keyring.
5. **`lib.rs` docs** still say fsck and key "are built in M13b" (not an owned file).
6. rust-skills conflicts: none.
