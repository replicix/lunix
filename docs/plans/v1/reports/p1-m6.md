### How it works

- **Memtable** (`HashMap` with an `xxh3` hasher): entries inserted in this process (hits are `Verified`) and relocated
  entries. **Runs** `index/<run:016x>` in the frozen format of on-disk-formats §17, written by a streaming writer
  (never all entries in RAM) that is byte-identical to `lunix_format::index_run::IndexRun::encode`; hits from a run
  are `Hinted`, always, also for ids this process wrote before `persist`.
- **Open** reads every named run once end to end: block CRCs, framing, ascending ids, block index, covered list,
  BLAKE3 `run_hash`, length rule, trailer id equals file name. It keeps per run a Bloom filter and the block directory
  (measured 2.38 B per entry) and the covered list. A lookup is: filter probe per run, newest first, binary search of
  the directory, one 4 KiB `pread`, CRC check, binary search in the block.
- **Persist rule.** `persist(upto)` writes, for every id in the memtable, its newest known location in a segment
  `<= upto`. A relocated (or duplicate-inserted) entry whose newest location is above `upto` stays in memory, and the
  run gets the previous location instead (a per-id chain of superseded memtable locations). So a crash before the new
  segment is named leaves the old entry current *and present*; without the chain the old entry would be in no run and
  the manifest would still claim its segment is covered. A run's `covered` list is the segments that have an entry in it.
- **Manifest** (`index/manifest`, `manifest.prev`): runs oldest first, condemned set, dropped set; replaced
  atomically (tmp, fsync, previous generation rewritten to `manifest.prev`, rename, directory fsync). Crash points
  `index.before_manifest_swap` (new manifest durable in `.tmp`, nothing renamed), `index.after_manifest_swap`,
  `index.after_condemn_flag` (flag durable and applied).
- **Damage.** If the newest manifest or any run it names fails validation, open falls back to the previous
  generation, then to an empty index, and rewrites a clean manifest at once; `open_report()` says so and lists the
  discarded runs (their files stay for GC). `catch_up` then restores every entry of the named segments from footers.
- **`catch_up(segments, footers)`**: ingests segments in the list that no run covers (higher segment id wins over an
  existing entry, an equal or newer one stands), then checks the existence of every other segment the index points
  into and drops the ones `footers` reports `NotFound`. An unnamed segment is never read.
- **`rebuild`**: fold of the footers in ascending segment order into the memtable, old runs leave the manifest
  (files stay for `all_runs` / GC). The caller `persist`s afterwards.
- **GC support**: `mark_condemned`/`unmark_condemned` (manifest, so they survive reopen; `get_for_dedup` never
  returns such an entry, `get`/`get_by_prefix` do, flagged), `relocate`, `drop_segment` (hidden at once, persisted
  in the manifest, purged from runs by the compaction that starts at the oldest run and cleared from the manifest
  when a compaction covers all runs), `delete_run` (also removes the run from the manifest if it names it, manifest
  first, then unlink), `all_runs` (reads trailers of every `index/<hex16>`).
- **Compaction**: size tiers by entry count (base 4096, factor 8); more than `max_runs_per_level` (default 8)
  adjacent runs of one level are merged into one at the end of `persist`, streaming, oldest window first. The merged
  run takes the window's place in recency order (adjacent merge only, so newest-wins stays correct).

## Decisions taken where the plan was silent

1. **Constructor and root**: `LsmIndex::open(root, ids: Arc<dyn IdAllocator>, id_len)`; runs get ids from the
   volume allocator (`persist` returns `RunRef`s and the caller names them in the next FULL).
2. **Hits after `persist` are `Hinted`** even for chunks this process wrote: the memtable entry leaves RAM when a
   run holds it. Costs one extra confirmation in M9, keeps the memtable bounded.
3. **`persist` returns the runs it created that are still named after compaction**; a run consumed by the merge it
   triggered is not returned.
4. **`delete_run` of a run the manifest names removes it from the manifest** (the contract test requires `runs()` to
   lose it). The safety check stays the caller's, as the trait says.
5. **Ordering rule for ingestion**: the higher segment id is the newer copy (`catch_up`, `rebuild`); ids are never
   reused and relocation always writes a higher segment.
6. **Fallback keeps the newest decodable manifest's condemned set**; if the manifest itself is damaged the previous
   generation's flags apply, which can lose a flag or bring back an unmarked one. The GC's own condemned list
   (`state/gc/condemned`) must be re-applied by M17 after open (documented in the crate docs).
7. **Level definition and window rule** for the "<= 8 runs per level" compaction as described above; only adjacent
   runs merge.
8. **Memory/streaming**: runs are written and merged streaming; `rebuild` and `iter_entries` hold the memtable (or a
   sorted copy of it) in RAM.
9. The model test places its directory on `/dev/shm` when it exists (logic test; `fsync` would make 5 000 sequences
   take hours). All other tests use the default temp dir.

## Spec gaps found

- DESIGN §7 / the plan say a run is "named by the next FULL"; `persist` also returns compaction outputs, which the
  FULL must name too (they are in `runs()`). The caller should always take `runs()`, not only the returned list.
- On-disk-formats §17.1 says `covered` is "the segments whose footer entries the run accounts for". M6 defines it as
  the segments that have an entry in the run, which is what makes the persist rule's shadow chain sufficient.
- R3 (spec update of 2026-11-12): `catch_up` and `rebuild` use footers only through `SegmentFooters`, so a footer is trusted exactly as far as that trait implementation opens it (M7: `MetaCodec::open` and the `seg_hash` check). M6 never reads an extent region and cannot recompute `seg_hash` itself.
- Compaction of runs does not keep tombstones: a dropped segment's entries are purged only by a merge that starts at
  the oldest run, and masked by the manifest `dropped` set until then (documented above).
