**`run_pass(false)`** finishes the pass in progress or asks for one (`request_pass`) and steps it until the
collector's pass counter moves, taking the coordinator mutex per step and releasing it between steps (sleeping
100 ms while the pass waits out its grace), so cuts and background steps go on. It returns the summary of the first
pass that ends after the call began (a background pass in progress counts). A pass the collector abandons (an
error in another caller's step) is asked for again, at most three times, then the call fails `Refused`; an error in
its own step is returned. Once the engine is quiesced (detach, `QuiesceAll`) the wait ends with `Closed`.
**`run_pass(true)`** is one `Collector::dry_run` on the coordinator. **`run_urgent`** is one `Collector::urgent`
on the coordinator; its moves go to the next cut. All three go through one helper (`with_collector`) that builds
the view exactly as the background step does and refuses (`Busy`) when the map is not at the tip.

**`GcStatus`** never waits: the engine keeps the collector's last `status()` in its own mutex; the daemon reaches
the engine through a weak map by volume name, not through the volume's slot mutex (a running `Gc` or an attach
may hold that). A volume that is not attached is idle.

**`Gc`** holds the volume's slot mutex only to clone the engine `Arc`; the pass itself runs without it, so a
detach or `QuiesceAll` never waits for a grace. Not attached: `Invalid`. `Closed` maps to `Busy` ("detached or
quiesced while the pass ran"); other errors map like store errors.

**The ladder.** `open_volume` registers `CompactStep(Weak<Engine>)` for `Compact`. It runs on the gate's thread
and calls `run_urgent(want)`; a closed engine frees 0. No deadlock: the coordinator never waits for the gate (it
only uses `reserve_headroom`, `release`, `transfer`), and a write parks in the gate before it takes a `write_seq`,
so a cut never waits for a parked write.

**Out of space (review S-2, ladder side).** When the host file system is full the gate may still admit writes
(its reading lags) while every cut fails in the destage with `NoSpace` (`AfterSpace`). Then no background step
runs and the ladder is never asked. Now `Inner::commit`, on a cut that failed with `NoSpace`, runs the urgent pass
on the coordinator (at most every 2 s; want = the dirty bytes, at least a chunk). And while cuts fail for space the
next cut applies no compaction re-hints (they stay in `moved`; their outputs are named all the same): a re-hint
applied before a destage that fails again would leave the map ahead of the tip, which stops every GC call, the
only thing that frees space.

## Deviations

- **`lunix-iface` changed** (two default methods on `Collector`): `GcControl::status` must not wait for the
  coordinator, and the engine names no implementation crate, so it needs the collector's status through the trait;
  a pass on request needs a way past the pass interval. Defaults keep the other implementations (engine test
  collectors) compiling; with the default `status` (state always idle) `run_pass` would ask three times and fail,
  which only matters for a test collector.
- **`Gc` does not hold the volume mutex for the pass** (the daemon's rule is one mutex per volume per call): a pass
  lasts at least the grace (60 s by default), and a detach or `QuiesceAll` must not wait for it. The quiesce ends
  the wait instead (`Closed`).
- **The engine runs the urgent pass itself when a cut fails for space**, besides the gate's ladder: the gate's
  ledger cannot see a full host file system before its next reading, and S-2's scenario needs the urgent pass
  exactly when cuts fail. The re-hint hold-back is in the M11 coordinator (`coord.rs`).
- **`tools/ci.sh`**: `stack_gc_ladder` and `control_gc` join the release stack tests.
