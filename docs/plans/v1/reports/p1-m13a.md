## What was built

`crates/lunix-cli` (`lunix` binary; everything lives in the library so tests reach it):

| file | content |
|---|---|
| `cli.rs` | the whole `clap` tree: `volume create/list`, `attach`, `detach`, `status`, `resize`, `space`, `gc`, `fsck`, `key` |
| `cmd.rs` | `run(cli, out, err) -> ExitCode`: dispatch, request building, error reporting and hints |
| `client.rs` | control-socket client: validates the request, frames it, checks `v` and `id`, maps error responses |
| `error.rs` | `CliError`, exit codes, control-character sanitising, the attach hints |
| `parse.rs` | size (`K/M/G/T`, powers of 1024), duration, floor, compression parsers; byte and UTC formatting |

| `render.rs` | human output of every response |
| `warn.rs` | the plain-volume texts, `check_plain_backend` (against the daemon) and `confirm_plain_backend` |
| `fsck.rs`, `key.rs` | M13b stubs: final argument types and `run_fsck(FsckArgs)` / `run_key(KeyArgs) -> ExitCode`, print "built in M13b", exit 2 |

Commands and options as in the plan, plus what the frozen iface carries:

- `volume create NAME --size S --dir D [--chunk 64K] [--encrypt|--integrity|--plain] [--passphrase|--passphrase-fd N]
  [--compress auto|lz4|zstd:N|none] [--id-len 16|32] [--key-file F]`; `volume list [--json]`.
- `attach NAME [--queues --depth --cpus --max-io-buf]` and, for the new iface fields, `--key-file`, `--passphrase`,
  `--passphrase-fd`, `--fingerprint`, `--credential-mode encrypted|integrity` (Credential.mode),
  `--on-journal-damage wipe|refuse`, `--allow-unverifiable-fork`. A first attach prints the rollback-floor note on
  stderr; failures with codes `fork_unverifiable`, `rollback`, `fork`, `journal_damage`, `downgrade`, `wrong_kmk`
  print a `hint:` line.
- `detach NAME`, `status [NAME] [--json]` (no name: every volume; includes the rollback floor), `resize NAME SIZE`,
  `space NAME [--floor X] [--on-full wait|error] [--full-timeout T] [--cache-max X] [--json]` (no option is a query),
  `gc NAME [--dry-run | --status] [--json]`.
- Exit codes: 0, 1 generic (also an unreachable daemon), 2 usage, 3 busy, 4 not found, 5 no space, 6 downgrade, wrong
  key, rollback, fork, fork_unverifiable, 7 journal damage (from `ErrorCode::exit_code`).
- Requests are validated with `Request::validate` before sending, so an invalid field is exit 2 with no round trip.
  Paths (`--dir`, `--key-file`) are made absolute client-side (the daemon has another working directory).

## Decisions taken

1. **Argument types of `fsck` and `key` live in `fsck.rs` and `key.rs`**, not `cli.rs`. M13b owns those two files and
   will need to adjust them (the plan's wording freezes `main.rs` and `Cargo.toml` only). The shapes are a best
   guess from the M13b step: `fsck NAME [--dir D] [--deep] [--rebuild-index] [--repair [--gc] [--truncate-tip]]
   [--key-file F] [--passphrase*] [--json]`; `key ls|add-slot|rm-slot NAME` with `--dir`, key options and
   `--unlock-key-file` / `--unlock-passphrase-fd`. The global `--socket` is copied into a `#[arg(skip)] socket`
   field before the stub is called. The `--help` snapshots of both are M13b's to regenerate.
2. **`--credential-mode` is explicit.** The CLI does not copy the volume's mode from `status` into the credential,
   because the request deciding the mode is the downgrade protection (ADR-11 F7). A passphrase or key file for an
   integrity volume needs `--credential-mode integrity`; the error hint says so.
3. **Passphrase sources.** TTY prompt (with a repeat prompt on create), `--passphrase-fd N`, or a key file the
   daemon reads. fd 0 reads standard input; other descriptors are opened through `/proc/self/fd/N` (a file or a
   pipe; a socket fails with a usage error). This keeps the crate free of `unsafe` and of new dependencies. A
   passphrase from a file is the file minus one trailing newline; empty and over 4096 bytes are usage errors.
4. **Terminal echo is switched off with `stty -echo`** on `/dev/tty` (restored by a drop guard), because the
   dependency list has no termios binding. If `stty` or `/dev/tty` is unavailable the command refuses and points at
   `--passphrase-fd`; it never reads a visible passphrase. A SIGINT during the prompt leaves echo off (the shell
   usually restores it). The TTY path has no automated test (no pty without libc or `unsafe`); the read logic it shares
   with the fd path is unit tested.
5. **`gc NAME --status`** shows the collector state (the `GcStatus` request exists in the protocol); `volume list`, `status`,
   `space` and `gc` take `--json`.
6. **`--full-timeout` needs a unit** (`500ms`, `60s`, `5m`, `1h`); a bare number is rejected rather than guessed.
   `--floor 0` (zero bytes) is accepted; every other size is greater than zero.
7. **Unreachable daemon is exit 1** with the socket path and OS error. Daemon messages are stripped of control
   characters before printing.
8. **`--id-len` accepts 16 or 32** as in the plan (the protocol also allows 0); `--chunk` must fit `u32`, the
   daemon validates the power of two.
9. **No `detach --release`, `quiesce` or `ping` subcommand**: the plan does not list them and `Detach` carries no
   release flag. Both `Ping` and `QuiesceAll` exist in the protocol if the lead wants thin wrappers.

## Spec gaps found

- DESIGN §16 says `backend add` on a plain volume "needs confirmation (`--yes` to skip it)"; the plan's M13a lists
  no `--yes` flag because the command is phase 2. The text and the confirmation helper are in place; phase 2 adds the flag.
- The plan's exit code list stops at 6; `ErrorCode::JournalDamage` is 7 in the frozen iface and the help says so.

## rust-skills conflicts

- `lint-missing-docs` / `doc-all-public`: public items carry docs, but `missing_docs` is not enforced (as in the
  other crates).
- `err-anyhow-app`: the CLI uses a small `thiserror` enum (`CliError`) rather than `anyhow` because every failure
  maps to an exit code and a class name; `anyhow` stays a declared dependency for M13b.
- `obs-tracing-over-log`: the CLI prints results and diagnostics to stdout/stderr by design and does no logging, so
  nothing can log a secret.
