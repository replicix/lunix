**The hook** (`check_gc`, called by every run; `repair: true` with `--repair --gc`):

- *Condemned list:* body version 1 decoded with `lunix_gc::CondemnedList`. A listed object that exists is the note
  `gc_pending` ("a pass deletes it after its grace and a recheck", or "a retained commit names or references it:
  the recheck un-condemns it"; referenced = named by a retained FULL, referenced by a retained root, or live in
  GC's mark). A listed object that is gone gives nothing. A body that does not decode is `condemned_invalid`
  (warning, ignored). `condemned_ids` returns segment, pack and run ids so the orphan check skips them.
- *Missing files:* left to the existing checks (`map_node_missing`, `map_entry_unresolved` after hint and index
  fallback); a missing file no retained root needs gives nothing.
- *Liveness:* `lunix_gc::liveness` over a `GcView` of the locked volume (fsck's scratch index, the tip's
  `RadixMap` over the packs, an offline no-op ledger, a manual clock), and fsck's own recount per segment from
  the roots GC pinned (`root_set`, so it follows GC's root rule on any base), fsck's decoded footers and the same
  index (hint confirmed against the footer, else the index's current copy confirmed, else stale-hint fallback by
  prefix; lean volumes hint-only). Any segment that differs is `gc_liveness`.
- *Dry run:* `Collector::dry_run` of a fresh `Gc`; non-zero work is one `gc_dry_run` note.
- *`--repair --gc`:* refused unless the chain verified, the tip walk completed, `state/pins` is not rejected, the
  real index opens and GC's mark resolves every entry. Then the real `Gc` over the real index runs passes until
  one frees nothing (at most 4): grace = the floor (10 s + 2 × `read_timeout`) on a manual clock the repair
  advances (fsck holds the lock, nothing is in flight), compaction off (`gc_live_threshold` at its smallest
  positive value, `compact_per_pass = 0`; a move would need a cut to name the output). Evidence objects are
  written as by any pass; the result is a `gc_dry_run` note with passes and bytes freed.

## Decisions taken

1. **Offline grace on a manual clock.** The plan says "condemn with floor grace"; offline nothing is in flight, so
   the repair advances a manual clock by the floor instead of sleeping 30 s per pass.
2. **No compaction offline**: its moves need a cut. A dry run after the repair can still list compaction work.
3. **The recount uses GC's root set** (`lunix_gc::mark::root_set`), so it stays equal across the N24 change on
   `lead/p1-gcfsck` (GC's retained set below `chain_floor`); fsck's own map walk and resolution are independent of it.
4. **The repair's result is a `gc_dry_run` note**: `repair.rs` records the `gc` action only when the hook returns
   a finding, and no repair code exists for GC; a dedicated code (e.g. `gc_repaired`) would read better.
