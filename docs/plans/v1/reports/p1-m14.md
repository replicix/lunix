## What was built (`crates/lunix-fsck`)

A library (`lunix_fsck::check(dir, &Options) -> Report`, which never errors and never panics: every failure is a
finding) and the `lunix-fsck` binary (`--deep`, `--json`, `--key-file`, `--passphrase-env`, `--rebuild-index`,
`--repair [--delete-orphans] [--gc] [--truncate-tip] [--reset-floor]`; exit 0 clean, 1 warnings only, 2 errors, 64
usage). Dependencies are the ones the manifest already had; `Cargo.toml` and `Cargo.lock` are untouched.

| module | content |
|---|---|
| `session.rs` | Parse `volume`, read `state/pins`, read the family keyring (`<dir>/families/<family>/keyring`), try the credentials (explicit key file, passphrase, then `<volume dir>/integrity.key`) through `check_attach` with the local pin and `keyring_seq`, then take the lock with `LocalVolume::open`. |
| `state.rs` | Step 1: `volume.json`, `state/pins` (read fresh on every run; a rejected file is `state_pins`, an error), `state/device`, pin objects, `state/gc/condemned`, leftovers, the checkpoint (a hint: damage is a warning). |
| `chain.rs` | Step 2 and R4: tip, chain down to `chain_floor`, genesis, `chain_floor` against `retain_last`, `created_at`, size, commits below the floor, `rollback`, `fork`, `fork_unverifiable` (the walk continues below `chain_floor` as the engine does). |
| `containers.rs` | Step 4 (R3): trailer, footer through `MetaCodec::open`, `seg_hash` over the whole region, a scan of every extent against the footer; `--deep` opens every extent (data: bounded decompression and recomputed id; nodes: tag). |
| `mapwalk.rs` | Step 3 (R2): the walk of every retained root. Each node: pack and location must be a footer entry, codec 0, header id equals the parent's hash, recomputed hash equals it, level, fanout and children fit. The tip is walked whole, the other retained roots skip what was walked. |
| `resolve.rs` | Entry resolution by hint, then by index confirmed against the full id, then again against an index rebuilt from the footers (the delete-time invariant); orphans; ratios (step 7) and bytes per category. |
| `indexcheck.rs` | Step 5: the index opened on a scratch copy (a check never writes to the volume), compared with the footers; `--rebuild-index`. |
| `journal.rs` | Step 6: every ring file read with `lunix_format::journal::scan_file`, merged by `write_seq` as recovery does; damage classified against the tip's `cut_seq`. |
| `repair.rs` | Step 8, see below. |
| `gc.rs` | The M17.B stub: `GcContext`, `check_gc(&GcContext) -> Vec<Finding>` (empty), `condemned_ids` (empty); `lib.rs` declares and calls it. |
| `code.rs`, `report.rs` | 65 stable codes with severity and meaning (also in `README.md`); findings, the report, text and JSON. |
| `tests/common/mod.rs` | The test builder: `lunix-crypto` (keys, codecs, commits, descriptor), `lunix-store`, `lunix-map`, `lunix-index`, plus ring files from the frozen journal types. Nothing is faked. |

**Repairs.** `--repair` removes `*.tmp` and `*.open`, rebuilds a damaged index (`--rebuild-index` does it on request,
also without `--repair`) and rewrites a damaged checkpoint (both slots zeroed, then one slot for the tip with no lane
tails and `id_high` of everything on disk). `--delete-orphans` deletes unreferenced segments and packs, records the
highest id on disk in the checkpoint first (ids are never reused), and refuses when the retained roots could not be
walked completely. `--truncate-tip` checks that the previous commit exists, authenticates, is a FULL and that its chain
verifies, then lowers the floor, sets the tip aside as `<seq>.damaged`, zeroes both checkpoint slots, and reports the
journal records the older cut can no longer cover. `--reset-floor` sets the floor to the verified tip and prints old and
new. After any repair the checks run again and the report shows the state after it.

## Proposal P1: lowering the rollback floor (stop for the lead)

`VolumeDir::raise_rollback_floor` is raise-only and `store_local_pins` keeps the floor, so nothing in `lunix-iface`
can lower the floor, and `--repair --truncate-tip` and `--reset-floor` need to (ADR-31: "only offline `fsck --repair
--truncate-tip` and an explicit, audit-logged operator reset lower it"). I did **not** touch the frozen crates and did
not write `state/pins` from fsck. fsck has a marked stub instead: `lunix_fsck::FloorLowering`, `Options::floor_lowering`
(`None` by default, so the binary refuses). Tests install a stand-in that rewrites `state/pins` with the format types.

Proposed change (iface, store, testkit):

```diff

+    /// at the same height), and returns the floor that was recorded before (`None`: none). ADR-31 names exactly

+    /// the new tip is the previous commit) and the explicit operator reset (`FloorReset::OperatorReset`). The
+    /// engine and the daemon never call it.
+    ///
```

## Deviations and open choices

1. **Floor lowering** is the stub above. The refusal happens before the first change, and the order in `--truncate-tip`
   is floor first, then set-aside, then checkpoint, so a rerun after a crash is idempotent.
2. **No `blake3` dependency.** `seg_hash` and the volume hash are computed through `CommitCodec::object_hash`, which is
   unkeyed BLAKE3-256 in every mode. The cost: one container's extent region is read into memory whole (a segment is
   16 MiB, a pack of a 1 TiB map about 30 MiB).
3. **No LZ4 dev-dependency.** The test builder has a small encoder of LZ4 blocks for runs (`tests/common`), used for
   compressible chunks and for the codec-1 node attack.
4. **`chain_floor` against `retain_last` is a warning** (`chain_floor`): the engine keeps the larger of the old floor and
   `seq - (retain_last - 1)`, so a raised `retain_last` legitimately leaves a higher floor, and the commit is
   authenticated anyway. A floor above the tip is an error.
5. **Orphans** are judged against every commit file still on disk, below `chain_floor` included: what such a commit names
   is garbage waiting for GC, not an orphan. Without this, a volume with `retain_last = 2` and no GC pass yet would exit 1.
   "Closed cleanly" is "no `*.open` or `*.tmp` file and no `state/device`".
6. **The condemned list body is not parsed** (its format is M17.A's, `docs/reference/gc.md`): `gc::condemned_ids` returns
   nothing until M17.B, so a condemned file that still exists shows as `orphan` or `crash_leftover` until then. An
   undecodable envelope is the warning `condemned_invalid` and is ignored.
7. **A damaged range with no valid record after it in its lane is the note `journal_tail`** (legal), also above the
   floor: a flip in the last record of a lane cannot be told from a torn write. Damage followed by a valid record above
   the floor is the error `journal_damage`; at or below it, a warning; valid records beyond the first gap are the
   warning `ignored_after_gap` (N4). Consequence for the random-flip gate: journal files are excluded from "never clean",
   which the report states.
8. **`--delete-orphans` is refused together with `--truncate-tip`** in one run (the checkpoint's `id_high` is zeroed with
   it and the ids of deleted objects could be reissued); alone it stores the highest id on disk in a fresh checkpoint
   slot before deleting.
9. **`--truncate-tip` is allowed on a tip that authenticates** (the map of a damaged tip can be the problem); it always
   needs the previous commit to authenticate and its chain to verify. The how-to that says it loses journal records C9
   already reclaimed is outside the paths M14 owns (`docs/how-to-guides`); the binary's help, the repair line and the
   crate README say it.
10. **Memory** is the tip's entries (about 64 bytes each), the footers of the containers (about 70 bytes per extent) and a
    set of distinct chunk ids. The 1 M-chunk volume in the gate has 64 distinct extents; a volume with millions of
    distinct extents needs RAM in proportion to them (about 100 bytes each).
11. **Exit code 64 for usage**, 2 when the volume is busy or cannot be opened (they are findings: `busy`, `credential`, ...).
12. **The index of a check is opened on a scratch copy** under the system temporary directory (opening it removes `*.tmp`
    files and may replace a damaged manifest). A volume with an index of many GiB needs that much temporary space.
13. **`gc.rs` contract for M17.B.** `GcContext` carries the locked `Session` and every fact the other checks found
    (`facts.segments`, `facts.packs`, `facts.walk`, `facts.referenced_segments`, `facts.named_*`, `facts.condemned`); M17.B
    can add fields without changing `check_gc`. `--repair --gc` calls it with `repair: true`.

## rust-skills conflicts

None with the project's rules. Choices where a skill rule was set aside on purpose: findings and a `Report` instead of
a `thiserror` error type (`err-thiserror-lib`: this crate's outcome is a report, an `Err` would hide the rest of the
checks); `Finding::code` is a `&'static str` from one documented table (`type-no-stringly`: scripts and M17.B add codes
without an enum change, and `Finding::new` asserts the code is in the table); `Options`, `Report` and `Finding` have
public fields and no `#[non_exhaustive]` (`api-non-exhaustive`: M13b builds `Options` with struct update and the crate is
not published). `#![forbid(unsafe_code)]`, `#![warn(missing_docs)]`, no `unwrap` or `expect` in the library.
